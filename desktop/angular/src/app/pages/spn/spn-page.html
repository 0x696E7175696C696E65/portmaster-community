Tor and WireGuard routing

Choose a route for each application. Start your tunnel or proxy before configuring Portmaster.

1. Enable the routing module

Enable Split Tunnel Module, then select the applications you want to route.

Open module settings ·Choose an application

2. Route through Tor

  1. Run a local Tor daemon with a SOCKS listener on a loopback address.
  2. In the selected application's settings, enable Use Split Tunnel.
  3. Set Network Interface to tor for 127.0.0.1:9050, or tor://127.0.0.1:9150 for a different port.
  4. Keep routing disabled for the Tor daemon itself to avoid a routing loop.

TCP uses the proxy. UDP is blocked. If the proxy cannot be reached, selected TCP connections fail without a direct fallback.

2. Route through WireGuard

  1. Start a tunnel in your WireGuard client using your own keys and peer configuration.
  2. Configure the tunnel routes and AllowedIPs in that client.
  3. Enable Use Split Tunnel for the selected application and set Network Interface to the tunnel interface name or its local IP.
  4. Keep routing disabled for the WireGuard client itself.

Portmaster binds traffic to the selected interface. Tunnel availability and route behavior depend on your operating system and WireGuard configuration.

3. Verify before relying on the route

Check the application's public IP with the tunnel active, then stop the tunnel and confirm the intended behavior. This page does not indicate a verified connection.

DNS uses Portmaster's configured resolver separately. Tor routing does not provide circuit isolation, onion hostname resolution, or Tor Browser fingerprint protection.
