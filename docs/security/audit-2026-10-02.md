# Security audit: 2026-10-02

Maintainer: bytefrxst. Baseline: `68370a16e7219fd4ad16364a407e3e922b376cda`.
Fix revision: the Git commit containing this report. Status: experimental source
update; stable release approval has not been granted.

## Scope and method

Reviewed the fork's Windows core API, authentication and diagnostics, browser and
native trust boundaries, selected-app routing, update ingestion and rollback,
Windows permission helpers, installer health checks, CI permissions and dependency
graphs. Extended the review to the driver command parser and buffered IRP helpers.
Used adversarial unit tests, Go vet/govulncheck, npm audit, RustSec cargo-audit,
production builds, and an isolated browser fixture under the production CSP.

This is a bounded source/dependency assessment, not an independent penetration
test, complete kernel review, NIST certification, or assurance against unknown
vulnerabilities. No live service, firewall rules, installed software, or signed
driver was changed. No credentials or real traffic history were used in the UI
fixture. Severity below is a qualitative project assessment, not a CVSS score.

## Findings and corrections

| ID | Severity and precondition | Root cause and correction | Regression evidence |
| --- | --- | --- | --- |
| API-01 | Medium; caller can reach API | Request limits trusted Content-Length; streamed/chunked bodies could allocate beyond the limit. Enforce actual 20 MB (20,000,000 bytes) HTTP and WebSocket limits. | Unknown/false Content-Length, bounded streamed bodies, oversized WebSocket close |
| API-02 | Low; invalid credentials | Short unknown API keys were sliced before a length check. Reject malformed/unknown credentials without a handler panic. | Empty/1–3 character Bearer and empty Basic cases |
| API-03 | Medium; access to diagnostics/logs | Public diagnostic/profiling endpoints and credential-bearing logs exposed sensitive data; CPU profiles accepted excessive durations. Require user authorization, redact secrets, cap profiling at one minute. | Unauthenticated diagnostics 401, public health 200, duration bounds |
| API-04 | Medium; malicious browser page or DNS rebinding | Permissive origins and loopback Host names weakened browser isolation. Check full scheme/host/port, loopback Host, and WebSocket origin; release mode rejects arbitrary extension origins. | Cross-origin/port/TLS/Host and WebSocket rejection cases |
| API-05 | Low; disconnected or stalled client | Full WebSocket response queues could retain senders after disconnect. Exit blocked sends when the session closes. | Full queue plus disconnect |
| UI-01 | High; attacker-controlled profile/process metadata | Generic sanitizer bypasses rendered profile names/paths as HTML. Use text bindings and Angular sanitization; remove bypass pipes and icon bypasses. Country flags now validate codes and create DOM images without string HTML. | Sanitizer lint with negative control; browser shows literal HTML-like names/paths with zero injected nodes/handlers |
| UI-02 | Medium; crafted links or compromised frontend | Host substring matching and inconsistent active link handlers misclassified destinations. Parse URLs, compare full origins, reject executable/file/unknown schemes and embedded credentials, constrain blob downloads; browser opens isolate the new window. | Origin/port/scheme/blob/credentials cases; active directive and browser/Electron handlers use the same policy |
| NATIVE-01 | Medium; frontend code execution | HTTP/WebSocket IPC could reach arbitrary native destinations outside browser checks. Restrict HTTP to local Portmaster API and WebSocket to its exact database endpoint; refuse redirects/proxies/custom headers and bound time, sizes and sessions. | HTTP URL confusion/redirect/stream limits and three vendored bridge tests |
| NATIVE-02 | Medium; malicious local server frame | Unchecked UTF-8 conversion accepted binary frames. Require text frames and checked decoding. | Invalid and valid-ASCII binary rejected; text retained |
| ROUTE-01 | Low; stalled local Tor daemon | Dial timeout did not cover SOCKS negotiation. Bound the full handshake and retain no direct fallback. | Local proxy accepts but stalls; deadline returns |
| ROUTE-02 | Medium; unsupported protocol/platform | Selected routing could retain acceptance for ICMP/raw protocols or silently ignore interface binding on unsupported OSes. Reject unsupported selected traffic after explicit exclusions; reject unsupported interface binding. | All 256 protocol values tested against routing verdict; existing proxy/interface tests |
| UPDATE-01 | Medium; untrusted download before verification | Unsigned download/decompression was unbounded. Limit index to 4 MiB and artifacts/unpacked data to 256 MiB, add timeouts and HTTPS redirect rules, preserve checksum/signature verification. | Advertised/chunked sizes, downgrade redirects, bounded reads and gzip checksum |
| UPDATE-02 | Medium; ACL or disk failure | Windows ACL failures were ignored in helpers, directories and staged artifacts. Propagate errors and prevent unsafe copies from becoming active. Failed purge preparation now aborts; rollback reports all failed restores. | Missing/invalid ACL policies, unsafe copy deletion, active path preservation, purge and multi-error rollback |
| DRIVER-01 | Medium; elevated administrator/SYSTEM device handle | Empty/truncated command buffers caused panic/out-of-bounds reads and packed casts. Source parser now bounds checks and decodes little-endian values; malformed writes are rejected. | Empty/short/misaligned parser cases and Go/Rust wire fixtures |
| DRIVER-02 | Medium; elevated administrator/SYSTEM device handle | Buffered I/O formed slices from null buffers, reported more output than initialized, and accessed IRPs after completion. Source handles null/empty buffers, reports filled bytes only and does not reuse completed IRPs. | Source review; full driver/Verifier validation remains outstanding |

Additional hardening: explicit Tauri command ACLs, trusted navigation, narrowed
shell scope, production CSP for both core-served and bundled UI, and removal of
unused clipboard-read permission. Public readiness now reflects the service's
actual readiness; the upgrade health check uses that endpoint.

Driver fixes are **source-only**. Device ACLs use administrator/SYSTEM access;
ordinary-user elevation was not demonstrated. The shipped signed driver has not
been rebuilt or patched. Full driver compilation stalled fetching pinned
bindings; WDK/Driver Verifier, signing and deployment are release requirements.
Microsoft documents the relevant [output initialization hazard](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/failure-to-initialize-output-buffers)
and [IRP completion lifetime](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/how-to-complete-an-irp-in-a-dispatch-routine).

| Scan | Before | After and interpretation |

| govulncheck 1.8.0, Windows core | 25 advisory IDs: 10 reachable, 4 imported-only, 11 module-only | 0 reachable/imported findings after Go 1.26.8 and x/crypto, x/net, x/image upgrades; one unimported module advisory remains |
| govulncheck 1.8.0, Linux core | Additional reachable BTF parser advisory in inherited cilium/ebpf 0.20.0 | 0 reachable/imported findings after upgrade to fixed 0.22.0; one unimported module advisory remains |
| cargo-audit 0.22.2, native lockfile | 20 vulnerability records | 0 vulnerability records; 12 informational warnings remain and are not suppressed |

The Go module-only advisory [GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932)
concerns unmaintained `x/crypto/openpgp`. No OpenPGP package is imported or called
by the reviewed core. Other x/crypto packages are required; retaining that module
is not evidence of OpenPGP reachability. Govulncheck source results distinguish
module presence from imported or reachable vulnerable functions. JSON scanner
exit codes alone were not treated as proof of a clean result.

The Linux scan separately detected [GO-2026-6238](https://pkg.go.dev/vuln/GO-2026-6238)
in Cilium's BTF parser, reachable through the eBPF loader. Upgraded `cilium/ebpf`
from 0.20.0 to the fixed 0.22.0 release; Windows excludes this Linux code path.

Rust informational warnings include ten unmaintained dependencies and two
soundness advisories. Linux-only `glib 0.18.5`
([RUSTSEC-2024-0429](https://rustsec.org/advisories/RUSTSEC-2024-0429.html)) remains
open: direct application use of the affected iterator was not found, but
transitive Linux reachability has not been excluded. `rand 0.7.3`
([RUSTSEC-2026-0097](https://rustsec.org/advisories/RUSTSEC-2026-0097.html)) is in a
build-generation dependency path; its advisory requires the `log` feature, which
is absent from the Windows compiled feature graph. Recheck other platforms and
future feature changes. The reviewed local WebSocket plugin fork retains upstream
licensing and provenance under `desktop/tauri/src-tauri/vendor`.

## Validation and evidence

- Windows: targeted gate passed API, updater, routing/firewall/profile/network/core
  tests, permission regressions, Go vet and a rebuilt core. Exactly two privileged
  updater integration tests skip on unelevated Windows; they passed on Linux.
- Linux API/updater/core/proxy/firewall tests and a core build passed after the
  final source and eBPF dependency fixes; the final Linux vulnerability scan
  reports zero reachable/imported findings. The rebuilt Windows core also passed
  a binary vulnerability scan.
- Frontend: libraries, production desktop, Tauri builtin and browser extension
  builds passed; six security tests, three existing UI tests and security lint
  passed. Supported locale loading was corrected during browser verification.
- Native: 13 workspace tests passed; locked Windows release build passed with
  the updated embedded frontend and CSP.
- Driver protocol: four Rust tests and Go/Rust fixture interoperability passed.
- Isolated browser fixture: dashboard/help loaded under production CSP; profile
  name and path markup rendered as literal text with no injected image or event
  handlers. Fixture incompleteness produces unrelated missing-record errors;
  this is not a full live backend/native desktop integration test.

Local evidence is retained outside Git in `outputs/security-audit-2026-10-02/`
with backend, frontend and native-routing subdirectories, scanner reports, build
logs, exit codes, browser proof and tool versions. Large binaries and raw logs
are not committed. An attempted Windows-wide `govulncheck ./...` could not load
untagged Linux eBPF packages; the successful Windows scan targets the shipping
core dependency graph. The inherited full `base/utils` suite also failed a
wall-clock execution-count assertion in `TestOnceAgain` under concurrent build
load; no production utility behavior was changed to hide that failure. Focused
permission tests pass, and the timing failure remains recorded for follow-up.

## Process changes and remaining gates

Pinned scanners and actions, read-only CI tokens, credential-free checkout,
regression/security lint, and native/driver protocol tests are configured for
GitHub and Gitea. GitHub also tests Linux updater integration. Upstream workflows
that publish to Safing's registry/cache are retained outside the active workflow
directory. Server branch protection, required checks and isolated Gitea runners
must still be verified on the actual servers.

This addresses SSDF PW.4/PW.7/PW.8 and RV.2/RV.3 through dependency triage,
root-cause fixes and regression evidence. Remaining release blockers include
signed patched driver validation, Linux glib triage, independent human review,
authenticated fork release provenance/SBOM, full routing/DNS/tunnel-stop tests,
and broader kernel/concurrency analysis. Private reporting remains deferred at
the maintainer's request. See the [risk register](risk-register.md) and
[release checklist](release-checklist.md).
