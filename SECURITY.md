# Security policy

This is an experimental community fork maintained by bytefrxst. The current development branch is the only version receiving fixes; no supported stable release or security SLA has been declared.

Private vulnerability reporting is deferred at the maintainer's request. No private reporting channel is currently available. Do not publish credentials, WireGuard private keys, browsing history, sensitive logs, or exploit details in public issues. If needed, open an issue asking the maintainer to arrange a private channel, without including vulnerability details. Do not send reports about this fork to upstream support.

For ordinary bugs, use this repository's [issue tracker](https://git.frxst.org/bytefrxst/portmaster/issues). Review and redact diagnostics yourself before attaching them. Get Help opens the repository; it does not upload diagnostics or create tickets automatically.

The maintainer should acknowledge reports, assess affected versions and exploitability, record remediation and root cause, add a regression test, and publish an advisory with a fix and mitigations. Targets, once private reporting is configured, are acknowledgement within three business days and an initial assessment within seven. These are proposed targets, not a current service guarantee.

See [the secure development process](docs/security/ssdf.md), [threat model](docs/security/threat-model.md), and [release checklist](docs/security/release-checklist.md). Adoption of this process is not NIST certification or an assertion of completed SSDF implementation.
